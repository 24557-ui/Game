# equipment 节点化扫描动画调整说明

记录时间：

```text
2026-10-10 11:00:47
```

本次调整目标：

1. 将上一版由 `Tween` 脚本驱动的 equipment 扫描动画，改为以 `AnimationPlayer` 节点和动画轨道为主。
2. 将短粒子与 research 用的长扫描粒子拆成两个 `GPUParticles3D` 节点。
3. 保留必要的 `main.gd` 状态逻辑，用于维护当前石头、研究状态和科技点。
4. 后续开发约定：除非用户特别说明，或确实必须用脚本处理复杂逻辑，否则优先使用节点、信号和动画资源完成效果。

涉及文件：

```text
game/assets/scene/equipment.tscn
game/assets/script/main.gd
game/assets/scene/trail_camera.tscn
```

本文件记录的方案会取代上一版“纯 Tween 代码驱动扫描动画”的方案。

## 一、新的 equipment 节点结构

`equipment.tscn` 中的节点结构调整为：

```text
equipment
├── Cylinder
├── GPUParticles3D
├── ScanGPUParticles3D
└── ScanAnimationPlayer
```

### 节点职责

#### `Cylinder`

保持 equipment 原有模型不变。

#### `GPUParticles3D`

普通状态下的短粒子效果。

当前参数：

```text
Amount = 8
Lifetime = 1.0
Preprocess = 0
Emitting = true
```

它不再承担 research 扫描时的长轨迹效果。

#### `ScanGPUParticles3D`

research 专用的长扫描粒子。

当前参数：

```text
Amount = 20
Lifetime = 2.5
Preprocess = 2.5
Emitting = false
```

默认不发射。点击 `Research` 后，由 `AnimationPlayer` 动画轨道将其 `emitting` 属性设为 `true`；扫描结束时再设回 `false`。

#### `ScanAnimationPlayer`

新的动画控制节点。

动画名：

```text
equipment_scan
```

动画长度：

```text
2.2 秒
```

它负责：

```text
equipment 向下倾斜
保持扫描角度
equipment 恢复原始角度
开启 / 关闭扫描粒子
```

## 二、AnimationPlayer 动画轨道

动画资源：

```text
Animation_equipment_scan
```

动画库资源：

```text
AnimationLibrary_equipment
```

动画名：

```text
equipment_scan
```

### 1. equipment 倾斜轨道

轨道属性：

```text
.:rotation:x
```

这里的目标节点是 `AnimationPlayer` 的父节点，即 `equipment` 根节点。

时间轴：

| 时间 | rotation:x | 说明 |
|---|---:|---|
| 0.0 秒 | 0 rad / 0° | 原始角度 |
| 0.3 秒 | 0.3839724354 rad / 22° | 向下倾斜到扫描角度 |
| 1.8 秒 | 0.3839724354 rad / 22° | 保持扫描角度 |
| 2.2 秒 | 0 rad / 0° | 恢复原始角度 |

动画阶段：

```text
0.0 → 0.3 秒：向下倾斜
0.3 → 1.8 秒：保持扫描姿态
1.8 → 2.2 秒：恢复原始角度
```

总时长：

```text
2.2 秒
```

插值方式：

```text
Cubic
```

相比线性插值，Cubic 会让倾斜和恢复过程更平滑。

### 2. 扫描粒子开关轨道

轨道属性：

```text
ScanGPUParticles3D:emitting
```

时间轴：

| 时间 | Emitting |
|---|---|
| 0.0 秒 | true |
| 2.2 秒 | false |

该轨道使用：

```text
Discrete
```

原因是 `emitting` 是布尔值，不应该在 `true` 和 `false` 之间连续插值。

## 三、粒子效果拆分

上一版本是把单个 `GPUParticles3D` 的参数直接改为：

```text
Amount = 20
Lifetime = 2.5
Preprocess = 2.5
```

这样普通状态和 research 状态共用同一个粒子节点。

本版本拆分为两个节点：

```text
GPUParticles3D       普通短粒子
ScanGPUParticles3D   research 长扫描粒子
```

### 普通短粒子

```text
Amount = 8
Lifetime = 1.0
```

粒子长度约为：

```text
Initial Velocity × Lifetime
= 1.0 × 1.0
= 1.0
```

### research 长扫描粒子

```text
Amount = 20
Lifetime = 2.5
```

粒子长度约为：

```text
Initial Velocity × Lifetime
= 1.0 × 2.5
= 2.5
```

### 发射密度

普通粒子：

```text
8 / 1.0 = 8 个 / 秒
```

扫描粒子：

```text
20 / 2.5 = 8 个 / 秒
```

因此扫描轨迹更长，但单位时间粒子密度仍保持一致，避免看起来变稀疏。

### Preprocess

`ScanGPUParticles3D` 保持：

```text
Preprocess = 2.5
```

当扫描粒子被开启时，系统会预先模拟完整的 `2.5` 秒粒子轨迹，因此开始扫描时就能看到较长光束，不需要等待粒子逐渐飞出。

### 缩放继承

两个粒子节点共用：

```text
ParticleProcessMaterial_equipment
```

该材质仍保持：

```text
particle_flag_inherit_emitter_scale = true
```

所以普通粒子和扫描粒子都会继承 equipment 在 `sojourner.tscn` 中的 `0.15` 缩放，之前修复的粒子尺寸问题不会被破坏。

## 四、main.gd 的节点化调整

文件：

```text
game/assets/script/main.gd
```

### 1. 新增 AnimationPlayer 引用

```gdscript
@onready var scan_animation_player: AnimationPlayer = $rover/equipment/ScanAnimationPlayer
```

解释：

- 从 `trail_camera.tscn` 根节点访问：

```text
rover
└── equipment
    └── ScanAnimationPlayer
```

- 脚本只负责调用动画，不再手动计算每一帧旋转。

### 2. 移除 Tween 相关状态

以下上一版代码已移除：

```gdscript
var scan_tween: Tween
var equipment_rest_rotation: Vector3
```

以及以下导出参数：

```gdscript
scan_tilt_degrees
scan_tilt_duration
scan_hold_duration
scan_return_duration
```

这些参数现在都体现在 `AnimationPlayer` 的关键帧中：

```text
扫描角度 → 22° 关键帧
倾斜时间 → 0.0 至 0.3 秒
保持时间 → 0.3 至 1.8 秒
恢复时间 → 1.8 至 2.2 秒
```

后续可在 Godot 编辑器的 Animation 面板中直接调整，不需要修改脚本。

### 3. 移除手动动画函数

上一版中的：

```gdscript
start_equipment_scan_animation()
```

已移除。

原来的：

```gdscript
create_tween()
tween_property()
tween_interval()
scan_tween.finished.connect(...)
```

不再需要。

现在的点击逻辑只调用：

```gdscript
scan_animation_player.play("equipment_scan")
```

### 4. 保留扫描目标状态

保留：

```gdscript
var scanning_rock: Node3D = null
```

原因：

```text
AnimationPlayer 负责视觉动画，
但它不负责判断哪块石头正在被研究。
```

`scanning_rock` 仍然用于锁定点击 `Research` 时的目标石头，防止扫描过程中目标切换或重复研究。

### 5. 点击 Research 后的脚本逻辑

当前逻辑：

```gdscript
func button_do_clicked():
	if current_rock == null or current_rock.researched or scanning_rock != null or not research_ui.visible:
		return
	scanning_rock = current_rock
	research_button_do.disabled = true
	label_do.text = "Scanning rock..."
	scan_animation_player.play("equipment_scan")
```

流程：

```text
确认当前石头有效
确认未研究
确认当前没有其他扫描
锁定 scanning_rock
禁用按钮
显示 Scanning rock...
播放 equipment_scan 动画
```

脚本不再参与角度计算或粒子开关，只负责进入正确的游戏状态并触发节点动画。

## 五、animation_finished 节点信号连接

文件：

```text
game/assets/scene/trail_camera.tscn
```

新增节点连接：

```text
rover/equipment/ScanAnimationPlayer.animation_finished
→ Node3D._on_equipment_scan_finished
```

场景文件中的记录为：

```text
[connection signal="animation_finished"
 from="rover/equipment/ScanAnimationPlayer"
 to="."
 method="_on_equipment_scan_finished"]
```

这属于节点信号连接，而不是在脚本中手动 `connect()`。

Godot 4.7 的 `AnimationPlayer.animation_finished` 信号会携带动画名称参数，因此处理函数签名为：

```gdscript
func _on_equipment_scan_finished(_animation_name: StringName) -> void:
```

函数内部仍然负责游戏状态结算：

```gdscript
var scanned_rock := scanning_rock
scanning_rock = null

if scanned_rock != null and not scanned_rock.researched:
	scanned_rock.researched = true
	tech_point += 5
	print(tech_point)

if current_rock != null:
	show_current_research()
elif current_rock == null:
	button_exist_clicked()
```

也就是说：

```text
视觉动画：AnimationPlayer 节点完成
动画结束通知：节点信号完成
researched / tech_point 状态：脚本完成
```

这是必要的分工。AnimationPlayer 可以动画节点属性，但不应直接理解“当前石头”或“科技点”的业务含义。

## 六、与上一版 Tween 方案的对比

| 项目 | 上一版 Tween 方案 | 本版节点方案 |
|---|---|---|
| 动画驱动 | `main.gd` 创建 `Tween` | `AnimationPlayer` 节点 |
| 倾斜角度 | 脚本导出变量 | 动画关键帧 |
| 倾斜时间 | 脚本导出变量 | 动画时间轴 |
| 保持时间 | `tween_interval()` | 动画关键帧保持段 |
| 恢复时间 | 脚本导出变量 | 动画时间轴 |
| 粒子长度 | 单个粒子节点直接改长 | 普通粒子 + 扫描粒子两个节点 |
| 扫描粒子开关 | 常规节点参数 | 动画布尔轨道 |
| 动画完成回调 | 脚本连接 Tween 信号 | 场景中的 `animation_finished` 信号连接 |
| 可视化调整 | 修改脚本参数 | 在 Animation 编辑器中拖动关键帧 |
| research 状态 | 脚本 | 脚本 |
| 科技点结算 | 脚本 | 脚本 |

## 七、如何在 Godot 编辑器中调整

### 1. 调整扫描角度

打开：

```text
assets/scene/equipment.tscn
```

选择：

```text
ScanAnimationPlayer
```

在 Animation 面板中选择：

```text
equipment_scan
```

选择 `0.3` 秒和 `1.8` 秒的 `rotation:x` 关键帧，修改角度即可。

当前角度：

```text
22°
```

### 2. 调整扫描时长

移动关键帧：

```text
0.3 秒：倾斜完成
1.8 秒：开始恢复
2.2 秒：完全恢复
```

例如希望总时长变成 `3.0` 秒：

```text
0.4 秒：倾斜完成
2.4 秒：开始恢复
3.0 秒：完全恢复
```

同时需要修改动画 Length 为：

```text
3.0
```

并把扫描粒子的 `emitting = false` 关键帧移动到 `3.0` 秒。

### 3. 调整扫描粒子长度

选择：

```text
equipment/ScanGPUParticles3D
```

在 Inspector 中调整：

```text
Lifetime
Amount
Preprocess
```

如果只延长 `Lifetime`，建议按比例增加 `Amount`，保持粒子密度。

当前比例：

```text
20 / 2.5 = 8 个 / 秒
```

### 4. 查看信号连接

打开：

```text
assets/scene/trail_camera.tscn
```

选择：

```text
rover/equipment/ScanAnimationPlayer
```

在 Node 面板的 Signals 中可以看到：

```text
animation_finished → Node3D._on_equipment_scan_finished
```

## 八、执行流程

### 1. 车辆进入 rocks 检测范围

```text
Area3D.body_entered
→ main.gd.body_enter()
→ 更新 current_rock
→ 显示 research UI
```

### 2. 点击 Research

```text
button_do_clicked()
→ scanning_rock = current_rock
→ Research 按钮禁用
→ Label 显示 Scanning rock...
→ ScanAnimationPlayer.play("equipment_scan")
```

### 3. AnimationPlayer 播放

```text
0.0 秒：ScanGPUParticles3D.emitting = true
0.0 → 0.3 秒：equipment 向下倾斜到 22°
0.3 → 1.8 秒：保持扫描姿态
1.8 → 2.2 秒：equipment 恢复 0°
2.2 秒：ScanGPUParticles3D.emitting = false
```

### 4. 动画结束

```text
animation_finished 信号
→ _on_equipment_scan_finished()
→ scanned_rock.researched = true
→ tech_point += 5
→ UI 刷新
→ Research 按钮恢复可用
```

## 九、后续开发约定

从本次调整开始，默认遵循以下习惯：

```text
除非用户明确要求纯脚本实现，或节点方案明显不合适，
否则优先使用节点、场景资源、AnimationPlayer、Timer、信号连接来完成功能。
```

优先级：

```text
1. 场景节点和 Inspector 参数
2. AnimationPlayer / AnimationLibrary
3. 节点信号连接
4. 必要的状态与业务逻辑脚本
```

脚本主要用于：

```text
游戏状态判断
目标选择
researched / tech_point 等数据维护
复杂输入处理
复杂动态逻辑
```

视觉动画、时长、粒子参数、节点开关等内容应尽量放到节点或动画资源中，便于在 Godot 编辑器里直接调整。
