# rover 完整视角与检测弹窗时序修复说明

记录时间：

```text
2026-10-10 17:01:12
```

本次修复针对三个反馈问题：

1. research 过场中的水平视角摄像头看不到完整 rover。
2. equipment 前方 Area 检测范围过小。
3. research 弹窗显示状态与实际物理检测状态存在时间或目标不同步的问题。

涉及文件：

```text
game/assets/scene/equipment.tscn
game/assets/scene/sojourner.tscn
game/assets/script/main.gd
```

## 一、修复水平视角无法看到完整 rover

### 1. 问题原因

原 `ScanCutsceneCamera` 位于 rover 侧面约 `1.4m` 处，并集中在 equipment 附近：

```text
Position = (1.4, 0.19072092, 0.7517834)
```

这个距离对完整 Sojourner rover 来说太近。摄像头视野主要被 equipment 和车身局部占满，无法在画面中放下整个 rover。

同时，摄像头 Transform 的朝向存在反向问题：实际 `-Z` 视线方向指向 rover 外侧，而不是指向 rover 中心。因此过场切入后容易出现看不到完整 rover，甚至画面方向不符合预期的情况。

### 2. 新摄像头位置

`game/assets/scene/sojourner.tscn` 中的：

```text
VehicleBody3D/ScanCutsceneCamera
```

位置调整为：

```text
Position = (4.2, 0.75, 0.0)
```

含义：

```text
X = 4.2   在 rover 右侧拉开距离
Y = 0.75  接近 rover 侧面中心高度
Z = 0.0   对准 rover 前后方向的中心
```

因为该摄像头是 `VehicleBody3D` 的子节点，车辆实际世界位置会叠加这个本地位置。在初始场景中，它的世界位置约为：

```text
(4.2, 1.378553, 0.0)
```

### 3. 修正水平朝向

摄像头视线现在指向本地 `-X` 方向，也就是从右侧水平看向 rover：

```text
camera_forward = (-1, 0, 0)
```

摄像头本身没有俯仰：

```text
camera_basis.y ≈ world +Y
```

因此仍然保持水平视角，只是现在正确朝向 rover。

### 4. 隐藏辅助层，避免干扰画面

新增 / 调整：

```text
Cull Mask = 1048435
```

该 Cull Mask 保留 rover 实体、车轮与 equipment，同时排除当前用于辅助显示的 Layer 4 / Layer 8 大型辅助网格，避免这些非主体物体在过场中遮挡画面。

### 5. 完整性验证

通过 headless 脚本计算 rover 主要可见部件的 AABB，包括：

```text
Sojourner/Body
Sojourner/Body_003
Sojourner/立方体
6 个车轮的 wheel/Body_004
equipment/Cylinder
```

当前可见 rover 范围约为：

```text
AABB Position = (-0.981611, -0.242350, -1.329604)
AABB Size     = (1.981317, 1.905914, 2.274032)
```

将该 AABB 的 8 个角点全部代入 `ScanCutsceneCamera` 视锥体检查，结果：

```text
full_rover_in_horizontal_frustum=true
```

说明当前水平视角可以覆盖完整 rover。

## 二、扩大 equipment 前方检测区域

### 1. 原范围

上一版检测盒最终世界尺寸为：

```text
0.75m × 0.75m × 1.0m
```

这个范围过窄，尤其是 X / Y 方向只有 `0.75m`。岩石碰撞体稍微偏移、车辆略有颠簸或岩石尺寸不一致时，视觉上看起来已经在 equipment 前方，但物理 Area 还没有触发。

### 2. 新范围

修改文件：

```text
game/assets/scene/equipment.tscn
```

节点：

```text
equipment/EquipmentDetectionArea/ForwardCollisionShape3D
```

本地 BoxShape 尺寸由：

```text
Vector3(5.0, 5.0, 6.6666667)
```

调整为：

```text
Vector3(10.0, 12.0, 20.0)
```

equipment 在 sojourner 中的缩放为：

```text
0.15
```

因此最终世界尺寸为：

```text
X = 10.0 × 0.15 = 1.5m
Y = 12.0 × 0.15 = 1.8m
Z = 20.0 × 0.15 = 3.0m
```

验证输出：

```text
area_world_size=(1.5, 1.8, 3.0)
```

### 3. 检测距离

`ForwardCollisionShape3D` 的本地 Z 偏移调整为：

```text
10.9866667
```

乘以 `0.15` 后相对 equipment 根节点偏移约：

```text
1.648m
```

检测盒长度为 `3.0m`，因此它覆盖 equipment 前方约：

```text
0.148m → 3.148m
```

考虑 equipment 模型前端大约在根节点前方 `0.136m`，实际有效检测范围约为：

```text
equipment 前方 0m → 3m
```

当前世界空间中心为：

```text
(-0.082862, 0.819274, 2.399783)
```

### 4. 检测方向

检测区仍然是 equipment 的子节点，因此跟随 equipment 本地 `+Z` 方向。车辆转向时，检测范围也会同步转向，保证检测的是 equipment 正前方，而不是固定世界方向。

## 三、重写弹窗与实际检测状态同步逻辑

### 1. 原问题

原逻辑主要依赖：

```text
Area3D.body_entered
Area3D.body_exited
```

一次性信号维护 `current_rock` 和 `nearby_rocks`。

这种方式在边界擦过、多块岩石重叠、物理体刚进入但 overlap 列表尚未完全刷新时，可能出现：

```text
视觉上岩石已经进入前方区域，但 UI 没有及时更新
岩石已经离开，但 UI 状态没有及时消失
多块岩石重叠时 current_rock 切换不合理
当前石头已研究后，新的可研究石头不能及时成为目标
```

### 2. 新增每物理帧刷新

`main.gd` 新增：

```gdscript
func _physics_process(_delta: float) -> void:
	_refresh_research_detection()
```

同时保留节点信号：

```gdscript
func _on_equipment_detection_body_entered(_body: Node3D) -> void:
	_refresh_research_detection()

func _on_equipment_detection_body_exited(_body: Node3D) -> void:
	_refresh_research_detection()
```

也就是说：

```text
Area 信号触发时刷新
每个物理帧也持续刷新
```

这样 UI 的 `current_rock` 与 `Area3D.get_overlapping_bodies()` 的实际物理状态保持同步，减少边界状态和信号时序造成的弹窗偏差。

### 3. 直接读取实际 overlap 状态

新增核心函数：

```gdscript
func _refresh_research_detection() -> void:
```

它每次读取：

```gdscript
equipment_detection_area.get_overlapping_bodies()
```

然后：

1. 将 `StaticBody3D` 转换为对应的岩石根节点。
2. 只保留拥有 `researched` 属性的有效岩石。
3. 计算每块岩石与 equipment 的距离。
4. 选择正确目标。
5. 目标变化时刷新 UI。
6. 没有目标时关闭 UI。
7. 扫描过程中不刷新，避免过场中目标被抢占。

### 4. 目标选择规则

当前规则为：

```text
1. 如果 current_rock 仍在检测区内且未研究，则优先保持不变。
2. 如果 current_rock 已研究，优先选择检测区内最近的未研究岩石。
3. 如果没有未研究岩石，才保留或显示已研究岩石，用于提示已完成。
```

这样可以解决“当前石头已研究后，弹窗一直停留在已研究状态，而新石头已经进入检测区”的问题。

### 5. UI 刷新规则

```text
目标变化 → show_current_research()
UI 隐藏但检测区仍有目标 → show_current_research()
目标消失 → button_exist_clicked()
扫描中 → 不刷新 UI
```

因此弹窗出现、切换、关闭都跟随当前实际 overlap 状态。

## 六、Godot 编辑器中后续调整方式

### 1. 调整检测长度

选择：

```text
equipment
→ EquipmentDetectionArea
→ ForwardCollisionShape3D
```

修改 Shape 的 `Size.z`。

换算公式：

```text
世界长度 = 本地 Size.z × 0.15
```

例如想要前方 `4m` 检测长度：

```text
4 ÷ 0.15 ≈ 26.6667
```

将 `Size.z` 改为：

```text
26.6667
```

同时将 CollisionShape 的 `Position.z` 调整为：

```text
Size.z × 0.5 + equipment 前端本地偏移
```

### 2. 调整检测宽度 / 高度

同样使用：

```text
世界尺寸 = 本地尺寸 × 0.15
```

当前：

```text
Size.x = 10.0 → 1.5m
Size.y = 12.0 → 1.8m
Size.z = 20.0 → 3.0m
```

### 3. 调整过场摄像头

选择：

```text
sojourner.tscn
→ VehicleBody3D
→ ScanCutsceneCamera
```

当前：

```text
Position = (4.2, 0.75, 0.0)
FOV = 65
Cull Mask = 1048435
```

如果仍希望在特定屏幕比例下留出更多边距，可以增大 `X` 距离，例如：

```text
4.6 或 5.0
```

不建议把摄像头重新贴近 equipment，否则完整 rover 会再次超出画面。
