# equipment 研究过场与粒子触发逻辑重写说明

记录时间：

```text
2026-10-10 16:32:17
```

本次是进一步重写，不等同于在上一版方案上简单调参。上一版中扫描粒子从动画开始就开启，并且会在 equipment 恢复阶段继续存在一段时间。本版将规则改为：

```text
粒子效果只在 research 检测动画中出现；
equipment 必须先旋转到指定扫描角度；
到达角度后才开始显示和发射粒子；
恢复旋转前先关闭并隐藏粒子；
平时不显示任何 equipment 粒子。
```

同时，点击 `Research` 后不再只是刷新按钮和播放 equipment 动画，而是进入一段完整的 UI 过场动画，显示研究过程。

涉及文件：

```text
game/assets/scene/equipment.tscn
game/assets/script/main.gd
game/assets/scene/trail_camera.tscn
```

---

## 一、重写后的核心规则

### 1. 平时状态

`equipment/GPUParticles3D` 默认为：

```text
Visible = false
Emitting = false
```

因此车辆移动、进入 UI、未点击 `Research` 时，不会出现任何 equipment 粒子效果。

### 2. 点击 Research 后

```text
隐藏 research_ui
锁定 scanning_rock
禁用 rover 交互与物理处理
播放 equipment_scan 动画
播放 research_cutscene 过场动画
```

### 3. equipment 旋转阶段

```text
0.0 → 0.3 秒：
equipment 从 0° 平滑旋转到 22°
粒子保持隐藏
```

### 4. 到达指定角度后

在 `0.32` 秒触发粒子：

```text
GPUParticles3D.visible = true
GPUParticles3D.emitting = true
GPUParticles3D.restart()
```

粒子没有在 `0.0` 秒出现，而是等到 `0.32` 秒，确保它发生在 `0.3` 秒到达 `22°` 之后。

### 5. 扫描保持阶段

```text
0.3 → 1.8 秒：
equipment 保持 22°
粒子保持显示和发射
研究进度条从 0 增加到 100
```

### 6. 恢复旋转前

在 `1.8` 秒：

```text
GPUParticles3D.visible = false
GPUParticles3D.emitting = false
```

粒子在 equipment 开始恢复角度之前就被关闭和隐藏，因此不会在恢复阶段继续显示。

### 7. 恢复阶段

```text
1.8 → 2.2 秒：
equipment 从 22° 回到 0°
```

### 8. 动画完成

```text
research_cutscene 隐藏
rover 恢复原来的 process mode
石头 researched = true
tech_point += 5
research UI 根据当前范围状态刷新
```

## 二、equipment 动画重写

文件：

```text
game/assets/scene/equipment.tscn
```

动画节点：

```text
equipment/ScanAnimationPlayer
```

动画名：

```text
equipment_scan
```

动画长度：

```text
2.2 秒
```

### 1. equipment 旋转轨道

轨道：

```text
.:rotation:x
```

关键帧：

| 时间 | Rotation.X | 说明 |
|---|---:|---|
| 0.0 秒 | 0° | 原始角度 |
| 0.3 秒 | 22° | 到达指定扫描角度 |
| 1.8 秒 | 22° | 保持扫描角度 |
| 2.2 秒 | 0° | 恢复原始角度 |

本版将旋转插值改为：

```text
Linear
```

原因是上一版使用 Cubic 时，关键帧之间出现了角度过冲，实际角度会超过 22°。这不符合“到达特定角度后才开始粒子”的要求。

线性插值能保证：

```text
0.3 秒时准确到达 22°
0.3 → 1.8 秒期间保持 22°
1.8 秒后才开始恢复
```

### 2. 粒子可见性轨道

轨道：

```text
GPUParticles3D:visible
```

关键帧：

| 时间 | Visible |
|---|---|
| 0.0 秒 | false |
| 0.32 秒 | true |
| 1.8 秒 | false |

说明：

- `0.32` 秒晚于 `0.3` 秒角度到达点。
- `1.8` 秒早于恢复阶段。
- 因此粒子只出现在设备已到达扫描角度且尚未恢复的阶段。

### 3. 粒子发射轨道

轨道：

```text
GPUParticles3D:emitting
```

关键帧：

| 时间 | Emitting |
|---|---|
| 0.0 秒 | false |
| 0.32 秒 | true |
| 1.8 秒 | false |

`Visible` 与 `Emitting` 同时控制，避免只停止发射但旧粒子仍显示的问题。

### 4. 粒子重启方法轨道

轨道：

```text
GPUParticles3D
```

方法：

```text
restart()
```

触发时间：

```text
0.32 秒
```

作用：

- 每次扫描开始时重置粒子系统。
- 配合：

```text
Preprocess = 2.5
```

- 让粒子到达触发点时立刻形成完整长扫描轨迹，而不是从第一个粒子慢慢生成。

## 三、粒子节点重写

本版移除了上一版额外的：

```text
ScanGPUParticles3D
```

现在只保留一个粒子节点：

```text
equipment/GPUParticles3D
```

这样逻辑更明确：

```text
这个节点就是 research 检测动画专用粒子节点。
```

当前参数：

```text
Visible = false
Emitting = false
Process Mode = Always
Amount = 20
Lifetime = 2.5
Preprocess = 2.5
```

### Process Mode = Always 的原因

点击 `Research` 后，`rover` 会被设为：

```text
PROCESS_MODE_DISABLED
```

用来形成不可操作的过场阶段。

但 `equipment` 是 rover 的子节点，因此以下节点必须设为：

```text
PROCESS_MODE_ALWAYS
```

需要保持处理的节点：

```text
ScanAnimationPlayer
GPUParticles3D
```

这样 rover 被禁用时：

```text
车辆控制脚本停止
VehicleBody3D 物理处理停止
equipment 扫描动画仍能播放
粒子仍能模拟
```

### 粒子长度

粒子初速度仍为：

```text
1.0
```

关闭重力后近似匀速直线运动，轨迹长度：

```text
1.0 × 2.5 = 2.5
```

粒子数量：

```text
20 个
```

发射密度：

```text
20 / 2.5 = 8 个 / 秒
```

因此扫描光束较长，同时不会显得稀疏。

### 尺寸继承

`ParticleProcessMaterial_equipment` 仍保持：

```text
particle_flag_inherit_emitter_scale = true
```

因此粒子继续继承 equipment 实例的 `0.15` 缩放，之前修复的尺寸问题不受影响。

## 四、research 过场动画

文件：

```text
game/assets/scene/trail_camera.tscn
```

新增节点结构：

```text
CanvasLayer
└── research_cutscene
    ├── Dim
    ├── CutsceneLabel
    ├── ScanProgress
    └── ResearchCutsceneAnimationPlayer
```

### 1. `research_cutscene`

全屏 Control 节点。

默认状态：

```text
Visible = false
Mouse Filter = Ignore
```

因此它平时不会显示，也不会挡住任何 UI 或鼠标输入。

### 2. `Dim`

全屏 `ColorRect`，用于过场压暗。

动画过程：

```text
0.0 秒：透明度 0
0.2 秒：透明度 0.58
1.9 秒：保持 0.58
2.2 秒：透明度 0
```

作用是让画面进入“过场”氛围，而不是普通 UI 弹窗。

### 3. `CutsceneLabel`

文本：

```text
Analyzing rock sample...
```

动画过程：

```text
0.0 秒：透明度 0
0.2 秒：淡入到 1
1.8 秒：保持 1
2.0 秒：淡出到 0
```

用于显示当前正在分析岩石样本。

### 4. `ScanProgress`

研究进度条。

范围：

```text
0 → 100
```

动画过程：

```text
0.3 秒：显示，值为 0
1.8 秒：值增加到 100
1.9 秒：隐藏
```

进度条只在扫描保持阶段显示，因此它与 equipment 到达扫描角度后的实际检测阶段对齐。

### 5. `ResearchCutsceneAnimationPlayer`

动画名：

```text
research_cutscene
```

动画长度：

```text
2.2 秒
```

动画轨道：

```text
research_cutscene:visible
Dim:color:a
CutsceneLabel:modulate:a
ScanProgress:visible
ScanProgress:value
```

全部过场表现都由 `AnimationPlayer` 轨道控制，不使用脚本逐帧更新 UI。

## 五、点击 Research 后的完整流程

`main.gd` 当前点击逻辑：

```gdscript
func button_do_clicked():
	if current_rock == null or current_rock.researched or scanning_rock != null or not research_ui.visible:
		return
	scanning_rock = current_rock
	research_ui.visible = false
	enter_research_cutscene()
	scan_animation_player.play("equipment_scan")
	research_cutscene_player.play("research_cutscene")
```

解释：

### 1. 防重复检查

```text
没有目标石头：不开始
石头已研究：不开始
已有扫描进行中：不开始
research UI 未显示：不开始
```

### 2. 锁定目标

```gdscript
scanning_rock = current_rock
```

确保动画结束时研究的仍然是点击时选中的石头。

### 3. 隐藏普通 research UI

```gdscript
research_ui.visible = false
```

点击后进入过场状态，普通按钮不再显示，避免扫描期间继续点击 `Research` 或 `Exist`。

### 4. 禁用 rover

```gdscript
enter_research_cutscene()
```

函数内容：

```gdscript
rover_process_mode_before_cutscene = rover.process_mode
rover.process_mode = Node.PROCESS_MODE_DISABLED
```

效果：

```text
车辆移动停止
驾驶输入停止
VehicleBody3D 物理处理停止
相机控制脚本停止
形成不可操作的研究过场
```

### 5. 同时播放两个节点动画

```gdscript
scan_animation_player.play("equipment_scan")
research_cutscene_player.play("research_cutscene")
```

两个动画长度均为：

```text
2.2 秒
```

因此 equipment 动作与 UI 过场保持同步。

## 六、过场结束与 research 结算

场景中已有节点信号连接：

```text
rover/equipment/ScanAnimationPlayer.animation_finished
→ Node3D._on_equipment_scan_finished
```

处理函数：

```gdscript
func _on_equipment_scan_finished(_animation_name: StringName) -> void:
	var scanned_rock := scanning_rock
	scanning_rock = null
	exit_research_cutscene()

	if scanned_rock != null and not scanned_rock.researched:
		scanned_rock.researched = true
		tech_point += 5
		print(tech_point)

	if current_rock != null:
		show_current_research()
	elif current_rock == null:
		button_exist_clicked()
```

恢复 rover：

```gdscript
func exit_research_cutscene() -> void:
	rover.process_mode = rover_process_mode_before_cutscene
```

结算顺序：

```text
1. 取出扫描时锁定的石头
2. 清空 scanning_rock
3. 恢复 rover 处理模式
4. 标记石头 researched
5. tech_point += 5
6. 根据当前是否仍在石头范围内刷新 UI
```

如果扫描期间车辆已离开石头范围：

```text
动画仍完成
原目标石头仍会被标记为 researched
research UI 隐藏
鼠标恢复捕获模式
```

## 七、与上一版方案的主要差异

| 项目 | 上一版 | 本版 |
|---|---|---|
| 普通粒子 | 单独短粒子节点常驻 | 无常驻粒子 |
| 扫描粒子 | 独立 `ScanGPUParticles3D` | 使用唯一 `GPUParticles3D` |
| 粒子开始时间 | 动画 0.0 秒 | 到达 22° 后的 0.32 秒 |
| 粒子关闭时间 | 动画 2.2 秒 | 恢复前的 1.8 秒 |
| 恢复阶段粒子 | 仍可能显示 | 完全隐藏 |
| 点击后 UI | 普通 UI 中显示文本 | 隐藏 UI 并进入全屏过场 |
| 过场表现 | 无 | 压暗、文本、进度条 |
| 过程进度 | 不可见 | ProgressBar 0 → 100 |
| rover 状态 | 扫描期间仍可操作 | 过场期间禁用 |
| 旋转插值 | Cubic，存在过冲 | Linear，准确到达 22° |
| 结算 | 动画结束 | 动画结束，并恢复 rover |
